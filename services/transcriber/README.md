# Telegram Transcriber Bot (с Groq AI)

Этот бот умеет принимать голосовые сообщения, аудиофайлы и кружочки из Telegram, быстро транскрибировать их с помощью Groq Whisper-Large-V3 и делать краткое содержание (summary) с помощью LLaMA 3.3 70B.

Публичное имя бота синхронизируется при старте через Telegram Bot API:

```text
Саммаризатор голосовых
```

## 🚀 Как запустить бота локально

1. **Получите токен бота:**
   - Откройте Telegram и найдите [@BotFather](https://t.me/BotFather).
   - Отправьте команду `/newbot`, придумайте имя и юзернейм (с окончанием `_bot`).
   - Скопируйте полученный HTTP API токен.

2. **Настройте переменные окружения:**
   - В этой же папке откройте файл `.env`.
   - Замените `ВАШ_ТОКЕН_ОТ_BOTFATHER_ЗДЕСЬ` на скопированный токен.
   - Убедитесь, что ваш `GROQ_API_KEY` там уже есть (я его добавил).

3. **Установите зависимости:**
   - Убедитесь, что у вас установлен Python (версии 3.8 или выше).
   - Откройте терминал в папке `apps/tg-transcriber-bot` и выполните:
     ```bash
     pip install -r requirements.txt
     ```

4. **Запустите бота:**
   ```bash
   python bot.py
   ```
   В терминале появится сообщение про запуск webhook server. Локальный health endpoint: `http://localhost:10000`.

## 🌍 Продакшен на Fly.io

Текущий продакшен живёт на Fly.io:

```text
https://tg-transcriber-bot.fly.dev
```

Бот работает через Telegram webhook. На старте он сам вызывает `set_webhook` на URL из `WEBHOOK_BASE_URL`.

### Деплой

```bash
fly deploy --app tg-transcriber-bot
```

Основные Fly secrets:

```text
TELEGRAM_BOT_TOKEN
GROQ_API_KEY
WEBHOOK_BASE_URL=https://tg-transcriber-bot.fly.dev
LEADS_CHAT_ID
LEAD_FORM_SECRET
LEAD_ADMIN_USERNAMES=denrech
YOUTUBE_COOKIES_BASE64
YOUTUBE_PROXY
GOD_USER_ID
ANTHROPIC_API_KEY
GITHUB_TOKEN
STATE_DB_PATH=/data/bot_state.sqlite3
```

Если volume `/data` не подключён, SQLite state DB будет создан в `temp/bot_state.sqlite3`
и переживёт только обычный рестарт процесса внутри той же машины. Для переживания redeploy
подключите Fly volume и задайте `STATE_DB_PATH=/data/bot_state.sqlite3`.

### Заявки с сайтов

Бот принимает заявки на endpoint:

```text
POST /lead
```

Чтобы узнать chat id для `LEADS_CHAT_ID`, напишите боту:

```text
/chat_id
```

Для быстрого запуска без Fly secrets можно написать боту в нужном чате:

```text
/set_leads_chat
```

По умолчанию эту команду может выполнить только Telegram-аккаунт `@denrech`.
Бот запомнит этот чат для заявок в SQLite state DB и fallback-файле. Самый жёсткий вариант
для продакшена — задать `LEADS_CHAT_ID` в Fly secrets.

Если заявки пришли до настройки чата, бот складывает их в SQLite state DB или fallback-файл `temp/pending_leads.jsonl`.
После `/set_leads_chat` он автоматически отправит накопленные заявки в выбранный чат.

Сайты должны отправлять заявки через свой серверный `/api/lead`, а не напрямую из фронтенда.
Если задан `LEAD_FORM_SECRET`, сервер сайта должен передавать его в заголовке `X-Lead-Secret`.

### Профильные заметки

Команда `/keep` хранит заметки отдельно для каждого Telegram-аккаунта:

```text
/keep
/keep текст заметки
/keep clear
```

Если у пользователя есть username, ключ профиля выглядит как `@username`, иначе используется `id:<telegram_id>`.
Стартовые заметки можно положить в `profile_notes_seed.json`; runtime-заметки пишутся в SQLite state DB
и fallback-файл `temp/profile_notes.json` или путь из `PROFILE_NOTES_PATH`.
`/keep`, `/keep list`, `/keep all` показывают все заметки профиля; длинный список отправляется несколькими сообщениями.

### Обратная связь

В приветствии `/start` есть кнопка `💬 Оставить обратную связь`.
Пользователь нажимает кнопку, пишет одно сообщение, а бот отправляет его в тот же админ-чат,
куда приходят заявки с сайтов. По умолчанию админом считается `@denrech`.

Если чат заявок ещё не задан, обратная связь сохраняется в SQLite-очередь или fallback-файл `temp/pending_leads.jsonl`
и будет отправлена после `/set_leads_chat`.

### PDF из фото, текста и голосовых

В личке бот собирает фото, картинки-файлы, текст и аудио/voice/video_note/video, пришедшие подряд,
в одну пачку с окном ожидания 2 секунды.

- После сбора пачки бот показывает кнопки действий, а не запускает обработку сам.
- Доступные действия: PDF max quality, собрать текст/расшифровку, текст в PDF, Word (.docx), summary, оформить сообщение, промт для Codex, отмена.
- `/pdf` и `/word` сохраняют последний собранный текст/расшифровку в файл. Если после команды добавить текст, файл будет сделан из него.
- `/pdf_prompt` и `/word_prompt` делают промт/ТЗ для сборки PDF или Word-документа из последнего контекста.
- Если в пачке только голосовые/аудио/видео без фото и текста, бот не спрашивает действие, а сразу делает расшифровку одним сообщением.
- Видео и аудио, отправленные как Telegram file/document (`video/mp4`, `video/quicktime`, `audio/*` и похожие расширения), тоже идут в расшифровку.
- Стандартный Telegram Bot API даёт боту скачивать файлы примерно до 20 МБ; большие видео нужно сжимать/резать или отправлять аудиодорожкой.
- JPG/PNG не уменьшаются и не сжимаются специально; HEIC/HEIF декодируются в PNG-страницы.
- Для оригинального качества фото лучше отправлять изображение как файл/document, потому что Telegram может сжимать обычные `photo`.
- Если итоговый PDF больше 49 МБ, бот попросит отправить меньше материалов или разбить их на несколько пачек.
- Если отправлены только фото без текста, текстовые действия покажут заглушки `[Фото N]`, а summary/сообщение/Codex попросят добавить текст или голосовое.

### OCR-версия

OCR выключен по умолчанию и включается только для конкретного Telegram-аккаунта:

```text
/ocr_on
/ocr_off
/ocr_status
/ocr_help
```

Когда OCR включён, пачки с фото/текстом показывают заголовок `OCR-версия включена`.
Кнопка сбора текста становится `📝 Собрать текст + OCR`, а summary/сообщение/Codex
используют текст из фото, captions, обычные сообщения и расшифровки аудио.

PDF max quality не запускает OCR и остаётся без сжатия/уменьшения. Если в пачке только аудио,
бот по-прежнему сразу делает расшифровку без выбора действия. Для OCR за один запуск лучше
отправлять не больше 10 фото.

### v3 «режим бога» (только для владельца)

Версия 3 добавляет ИИ-ассистента и агента поверх бота. Всё **выключено по умолчанию**
и включается отдельной командой `/v3_on`. Мощные функции доступны **только одному
Telegram-аккаунту**:

- задайте `GOD_USER_ID` в Fly secrets (свой числовой id — узнать через `/myid`). Это
  главный гейт: id нельзя подделать через Bot API;
- если `GOD_USER_ID` не задан, fallback идёт по `GOD_USERNAME` (по умолчанию `denrech`),
  но это слабее — для выполнения кода лучше задать именно id.

Команды (в личке, только владелец):

```text
/v3_on        включить режим
/v3_off       выключить
/v3_status    статус
/v3_help      подсказка
/myid         узнать свой Telegram id
/ask <вопрос> спросить нейронку по последней расшифровке/материалам (или ответом на сообщение)
/agent <задача> Claude-агент в песочнице: bash + чтение/запись файлов
/self <инструкция> Claude правит СВОЙ код, показывает diff и по кнопке пушит в main
```

`/ask` работает сразу на Groq (`GROQ_API_KEY` уже есть). Если задать `ANTHROPIC_API_KEY`
в Fly secrets — `/ask` и агент начинают думать через Claude (модель по умолчанию
`claude-opus-4-8`, меняется через `ANTHROPIC_MODEL`).

`/agent` и `/self` требуют `ANTHROPIC_API_KEY`. `/self` дополнительно требует
`GITHUB_TOKEN` (fine-grained PAT с правом Contents: Read and write на репозиторий) —
без него Claude покажет diff, но не сможет запушить. Перед каждым push бот показывает
diff и спрашивает подтверждение кнопкой; правки делаются в свежем клоне, живой процесс
не трогается до отдельного Fly deploy/CI.

Переменные env для v3 (все опциональны, кроме нужных конкретной функции):

```text
GOD_USER_ID         числовой Telegram id владельца (главный гейт)
GOD_USERNAME        fallback по username, по умолчанию denrech
ANTHROPIC_API_KEY   ключ Claude — включает Claude-мозг и агента
ANTHROPIC_MODEL     модель Claude, по умолчанию claude-opus-4-8
ANTHROPIC_EFFORT    усилие рассуждения: low|medium|high|max, по умолчанию high
GITHUB_TOKEN        PAT для git push в /self (Contents: read/write)
GITHUB_REPO         owner/repo, по умолчанию aireden14/tg-transcriber-bot
```

⚠️ Это по сути выполнение произвольного кода на сервере и самодеплой, поэтому доступ
жёстко ограничен одним аккаунтом и отдельной командой. Держите `GOD_USER_ID` и
`GITHUB_TOKEN` в секрете.

#### v3: ассистент по контенту, зрение, напоминания, память

Когда v3 включён:
- После аудио/текста/фото/PDF бот даёт кнопки: 🧠 Summary и быстрые ссылки в
  ChatGPT/Grok — открывают сервис с уже готовым сообщением по этому тексту
  (предложить вопросы / задать свой). Ссылки-кнопки работают и в обычном режиме
  (v1), не только в v3.
- Последний текст можно сохранить командами `/pdf` и `/word`; режимы `/mode pdf`
  и `/mode word` готовят промты/ТЗ для сборки таких документов.
- Любой обычный текст в личке = команда ассистенту над текущим контентом
  («переведи», «сделай список»). PDF-сборка остаётся кнопкой на фото/материалах.
- Зрение: присланные фото/скрины бот понимает (Claude vision, иначе Groq vision-модель).
- PDF-документ: извлекает текст и предлагает действия.
- Ответ реплаем на любое сообщение бота = вопрос к ИИ.

Память (второй мозг): присланное и диалог пишутся в `temp/v3_memory.jsonl`.
`/recall <запрос>` — найти и ответить по памяти; `/memory` — счётчик; `/forget` — очистить.

Напоминания: `/remind завтра в 10 позвонить` (или просто «напомни …» текстом),
`/reminders` — список с кнопками удаления. Часовой пояс — env `V3_TZ` (по умолчанию `Asia/Almaty`).

Доп. env:

```text
V3_TZ             часовой пояс напоминаний (по умолчанию Asia/Almaty)
V3_REMINDERS_PATH путь к JSON напоминаний (по умолчанию temp/v3_reminders.json)
V3_MEMORY_PATH    путь к памяти (по умолчанию temp/v3_memory.jsonl)
```

⚠️ ФС Fly без volume эфемерна: SQLite/file state переживает обычный рестарт машины, но может
сброситься при redeploy. Для постоянной памяти нужен Fly volume `/data` и `STATE_DB_PATH=/data/bot_state.sqlite3`
или внешнее хранилище.

### YouTube downloader и блокировки

YouTube иногда блокирует скачивание с датацентровых IP Fly. Если бот пишет про блокировку,
403, проверку "not a bot" или недоступность видео, добавьте в Fly secrets cookies YouTube через
`YOUTUBE_COOKIES_BASE64`. Cookies не нужно коммитить в репозиторий.

Локально подготовить значение можно так:

```bash
base64 -i youtube-cookies.txt | pbcopy
```

Файл `youtube-cookies.txt` должен быть в формате Netscape cookies.txt.
Если cookies не помогают, используйте `YOUTUBE_PROXY` с разрешённым proxy-сервером.

### Вариант 2: PythonAnywhere
1. Зарегистрируйтесь на [PythonAnywhere](https://www.pythonanywhere.com/).
2. Перейдите во вкладку **Files** и загрузите туда файлы: `bot.py`, `requirements.txt` и `.env`.
3. Перейдите во вкладку **Consoles**, создайте новую `Bash` консоль.
4. Выполните: `pip install --user -r requirements.txt`
5. Для того чтобы бот работал постоянно, его можно запускать через вкладку **Tasks** (Always-on tasks), указав путь до скрипта: `python3 /home/ваш_логин/bot.py`. Для текущего проекта основной прод — Fly.io.

## Ограничения
- Максимальный размер файла для скачивания ботом — 20 МБ (ограничение Telegram API). Этого более чем достаточно для длинных голосовых.
- Если голосовое длится больше часа, могут потребоваться изменения в коде для разбиения аудио (но обычно люди столько не записывают).
